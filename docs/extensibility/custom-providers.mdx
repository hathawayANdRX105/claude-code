# Custom Providers and Model Lists

`~/.claude/providers.json` declares third-party model endpoints in either wire
format: OpenAI Chat Completions (`openai-compat`) or the Anthropic Messages API
(`anthropic`). Every provider's listed models appear in the `/model` picker as
`providerId/modelId` rows alongside the built-in options; a session can mix
providers per request.

## Minimal example

```json
[
  {
    "id": "wildtoken",
    "kind": "openai-compat",
    "baseUrl": "http://localhost:3100/v1",
    "apiKeyEnv": "WILDTOKEN_API_KEY",
    "defaultModel": "grok-4.7",
    "compatRule": "permissive",
    "models": [
      { "id": "grok-4.7", "contextWindow": 500000 },
      { "id": "kimi-k3", "name": "Kimi", "contextWindow": 500000 },
      { "id": "gpt-6-astra", "contextWindow": 370000 }
    ]
  }
]
```

`/model` then shows exactly `grok-4.7`, `Kimi`, `gpt-6-astra`.

## Provider fields

| Field | Required | Meaning |
| --- | --- | --- |
| `id` | yes | kebab-case id, used by `/providers use <id>` |
| `kind` | yes | wire protocol: `openai-compat` (OpenAI Chat Completions) or `anthropic` (Anthropic Messages API, e.g. a relay/proxy serving `/v1/messages`) |
| `baseUrl` | yes | full base URL. `openai-compat`: include the `/v1` suffix when the endpoint needs it. `anthropic`: the base the SDK's client targets — the SDK appends `/v1/messages` itself, so do NOT add a `/v1` suffix |
| `apiKeyEnv` | yes | name of the env var holding the key — never the key itself |
| `defaultModel` | yes | model id used when the provider is activated |
| `compatRule` | yes | `permissive`, `strict-openai`, `cerebras`, `groq`, or `deepseek`; ignored for `kind: "anthropic"`
| `models` | no | model ids this provider serves; see below |
| `fastModel` | no | the provider's fast/background role model (reserved; declared but not consumed in this release) |

## Model fields

| Field | Required | Meaning |
| --- | --- | --- |
| `id` | yes | exact model id sent to the endpoint |
| `name` | no | label shown in `/model`; defaults to `id` |
| `contextWindow` | no | real context window in tokens; defaults to 200k |

## Anthropic wire providers (`kind: "anthropic"`)

Use this for endpoints that speak the **Anthropic Messages API** — relays,
proxies, or gateways that serve `/v1/messages` (including Claude models or
models exposed in Anthropic wire format). Requests for a provider-prefixed
model (`<id>/<model>`) of such a provider are sent over the native Anthropic
path — same request shape as first-party Claude — with the provider's own
`baseUrl` and API key. `compatRule` has no effect; the native wire needs no
compat profile.

```json
[
  {
    "id": "claude-relay",
    "kind": "anthropic",
    "baseUrl": "https://relay.example.com",
    "apiKeyEnv": "RELAY_API_KEY",
    "defaultModel": "claude-sonnet-4-5",
    "compatRule": "permissive",
    "models": [
      { "id": "claude-sonnet-4-5", "contextWindow": 200000 }
    ]
  }
]
```

Activation (`/providers use claude-relay`) exports `ANTHROPIC_BASE_URL`,
`ANTHROPIC_API_KEY`, and `ANTHROPIC_MODEL` instead of the `OPENAI_*` set,
because the session's native (first-party) API path is what these providers
route through. Provider-prefixed models route per request and work even when
the global session is in OpenAI-compat mode.

## How a provider is matched to the running session

There is no endpoint matching: a provider's `baseUrl` is not compared against
any session env var. A provider takes effect **per model value** — a model
string of the form `<providerId>/<modelId>` (first slash splits the provider
from the model; model ids may contain further slashes) routes that request to
the named provider's endpoint and wire format. A bare model id routes to the
globally configured provider as before.

Built-in providers (cerebras, groq, qwen, deepseek) are always available; a
user entry with the same `id` replaces the built-in one.

## Where the model list applies

- The `/model` picker lists every configured provider's models as
  `providerId/modelId` rows, grouped by provider, alongside the built-in
  options — one session can mix providers (each prefixed value routes to its
  own provider).
- The context window for auto-compact and token accounting comes from
  `contextWindow`, resolved by the provider named in the model's prefix.
- Selecting a provider-listed model skips the live model-probing call, so no
  request is sent to validate it.

## Precedence for context window

Highest wins:

1. `contextWindowOverrides` in `~/.claude/settings.json` (per model id)
2. `CLAUDE_CODE_MAX_CONTEXT_TOKENS` (ant builds only)
3. `contextWindow` from `providers.json`
4. Built-in detection, then the 200k default

`~/.claude/settings.json` therefore still overrides an individual model when
both files declare a window for it.

The `[1m]` suffix used by built-in aliases is checked after the provider value.
It only matters for built-in aliases (`sonnet[1m]`, `opus[1m]`); provider rows
use `providerId/modelId` and are not affected by the suffix.

## Activating a provider

`/providers use <id>` prints shell exports; it does not change the running
process. Put the same values in `settings.json` `env` to make them apply on
startup. The exported set depends on `kind`:

`openai-compat`:

```json
{
  "env": {
    "CLAUDE_CODE_USE_OPENAI": "1",
    "OPENAI_BASE_URL": "http://localhost:3100/v1",
    "OPENAI_API_KEY": "${WILDTOKEN_API_KEY}",
    "OPENAI_MODEL": "grok-4.7"
  }
}
```

`anthropic` (activates the native first-party path pointed at the relay):

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:3100",
    "ANTHROPIC_API_KEY": "${WILDTOKEN_API_KEY}",
    "ANTHROPIC_MODEL": "claude-sonnet-4-5"
  }
}
```

Activation sets the session's *bare* (default) model. Provider-prefixed model
values route per request and work even when the global session runs in a
different provider mode.

`ANTHROPIC_CUSTOM_MODEL_OPTIONS` is a separate mechanism: it appends bare model
ids to the built-in list. Prefer `providers.json` `models` when you want
provider-grouped rows.

## Model switch precedence

`/model` persists to the top-level `model` field, but the session starts with
the `ANTHROPIC_MODEL` env var when it is set — that one wins. Remove it from
`settings.json` `env` if you want the saved `model` field to take effect.
