# 0001. 共享进程契约

**Date**: 2026-09-24
**Status**: In Progress

## Summary

一个用户只跑一份 Claude 进程。你打开的终端、后台任务和远程连接都连到这份进程上，不再各自扛一份 Bun 运行时。关掉终端就把这个会话从内存拿掉，下次打开从原来的会话文件装回来。第二个终端打开同一个会话时，会得到一份分叉（fork，从那一刻拷出来的新会话），原来那份继续跑。

## Context

现在每开一个终端，就会新起一份 Bun 运行时和一份 Claude。ccb 开一次就付一次这份内存。已有的 `claude daemon` 是一个监督进程再拉 worker 子进程，给远程控制用，它不让多个会话共用一份运行时。后台会话（`ps`、`logs`、`attach`、`kill`、`--bg`）也是各自独立的进程。

会话内容今天已经写在项目目录的 `<sessionId>.jsonl`。这份契约不改这个文件格式，也不另起存储。进程内只放还活着的会话。

> ⚠️ Premise note: 一个会话单独退，只能挡住这个会话自己的异常。原生模块或运行时本身崩溃，仍然会带走整份进程，其它会话一起断。要真隔离就得把会话放回子进程，内存节省就没了。这份契约接受这个边界，不承诺进程级隔离。

这一份契约同时管交互终端、后台会话、远程控制。三种连接进同一个进程，但这一刀只把契约写定。交互终端先做，后台和远程按 scope 的后面几刀再搬进来。

## Requirements

**User stories**:
- 作为一个开着多个终端的人，我要后面的终端连上已经在跑的进程，这样我不用为每个终端再付一份运行时。
- 作为一个会关掉再打开的人，我要同一个会话从原来的会话文件装回来，这样对话还在，而且仍然落在这一份进程里。
- 作为一个发现会话已被占用的人，我要得到一份分叉而不是被拒绝或把别人顶掉，这样两边都能继续。
- 作为一个跑后台任务或远程连接的人，我要它们住进同一份进程，这样它们也不再各起一份运行时。

**Acceptance criteria**:
- **AC-1**: 同一用户的第二个交互终端连上已有进程，操作系统里的 Claude 进程数不增加。
- **AC-2**: 第一个终端发现没有活着的进程时，拉起这一份进程再连接。地址被占用但锁文件里的进程号已经不在时，先清掉残留地址再拉起。进程号还活着，或锁文件读不出来，就不删。
- **AC-3**: 关掉一个会话的最后一个终端后，这个会话不再留在进程内存里。再次打开时，从 `<项目目录>/<sessionId>.jsonl` 装回同一份进程。
- **AC-4**: 一个会话已有交互终端附着时，第二个终端打开它会得到一个新会话编号。新会话拷走原会话已经落盘的对话，加上当前这一轮已经流出来的输出。还没流出来的不拷。原会话继续跑，不受影响。
- **AC-5**: 一轮对话还在跑时终端断开，这一轮停止。写完的行保留。写到一半的那一行丢掉。这一轮不再继续。
- **AC-6**: 一轮对话里抛出的异常只停这一轮，会话变成 stopped。进程起不来，或原生模块把进程打崩，才算整份进程死。进程重新拉起后，会话从磁盘装回，不从内存恢复。
- **AC-7**: 同一用户的所有会话共用这一份进程里的一份登录态。一个终端退出登录，其它会话也失去这份登录。
- **AC-8**: 后台会话是这份进程里的一个没有终端的会话。这一轮结束或失败后落盘，然后从内存拿掉。`ps`、`logs`、`attach`、`kill` 操作的是这份进程里的会话，不再为它新起进程。
- **AC-9**: 远程连接是这份进程里的一个会话，用进程里的那一份登录态。监督进程不再为远程控制拉 worker 子进程。
- **AC-10**: 默认地址是每个用户一个固定本地地址。Linux 用用户运行时目录里的 Unix socket。Windows 用固定名字的命名管道。`CLAUDE_SHARED_SOCKET` 可以改这个地址。没设置时用默认地址。


**Pros**:
- 运行时、登录、模型连接只付一份。
- 会话文件格式不用迁移。

**Cons**:
- 原生层崩溃会带走所有正在附着的会话。
- 一份登录态意味着退出登录是全局的。

### Option 2: 每个项目一份进程

每个仓库自己一个进程，项目之间隔开。

**Pros**:
- 一个仓库的崩溃不碰另一个仓库。

**Cons**:
- 同时开几个仓库，运行时还是要付好几份。这和这次要省的内存相反。

### Option 3: 只把重的部分抽出去

REPL 进程还在，只把 MCP、模型连接、索引放到一个共享进程。

**Pros**:
- 改动面小。

**Cons**:
- 每个终端仍然扛一份 Bun 和一份 REPL。省得少，也达不到瘦终端。

## Decision

**Chosen option**: Option 1: 一个用户一份进程，会话在进程内

同一用户的交互终端、后台会话、远程连接都进这一份进程。会话磁盘格式不变。

**Implementation skills**: 无。本仓没有 `.agent/skills/`，这份契约不引入新库。

## Rationale

要省的是每开一个终端就再付一份 Bun 加一份 Claude。每个项目一份进程，几个仓库同时开着就还是好几份。只抽重活，终端进程本身还在。所以身份是每个用户一份，三种连接都进来。

会话文件已经是 `<项目目录>/<sessionId>.jsonl`。进程内不留关掉的会话，恢复只读这个文件，避免两套存储。

第二个终端选择分叉，是因为拒绝会挡住你，顶掉会停掉还在跑的那一份。拷到分叉那一刻，两边从同一份对话往下走，原会话不被打断。

崩溃隔离只做到会话自己的异常。原生崩溃带走整份进程，是这份内存节省的代价，不在这份契约里用子进程补上。

## Feature design

**Data model sketch**:

进程（每个用户一份，活在内存里，不落盘）:
- `address`，必填。默认本地地址，或 `CLAUDE_SHARED_SOCKET`。
- `lock`，必填。锁文件里写着持有者的进程号。这个进程号还活着，残留地址就不能删。
- `auth`，一份，可空。空表示还没登录。

会话（活着时在进程内，内容在现有 jsonl）:
- `sessionId`，必填，沿用现在的会话编号。
- `parentSessionId`，可空。只有分叉出来的会话有，指向被分叉的那份。
- `cwd`，必填。工作目录。
- `state`，必填。`idle`（空闲）、`running`（跑一轮）、`stopped`（这一轮已停）、`released`（已从内存拿掉）。
- `transcriptPath`，必填。`<项目目录>/<sessionId>.jsonl`。

连接（附着时才在，不落盘）:
- `connectionId`，必填。
- `kind`，必填。`interactive`（交互终端）、`background`（后台，没有活连接）、`remote`（远程）。
- `sessionId`，必填。交互和远程一次只附着一个会话。

轮次（活着时在进程内）:
- `turnId`，必填。
- `sessionId`，必填。
- `running`，必填。连接断开或这一轮结束时变为假，并把已有对话落盘。

**State transitions**:

会话：`idle` 到 `running`（开始一轮），`running` 到 `stopped`（一轮结束、失败，或终端断开），`stopped` 到 `released`（最后一个连接没了，或后台这一轮已经落盘）。`released` 后再打开，从 jsonl 装回，成为新的 `idle`，不是把旧对象留在内存里。

分叉不是状态。它新建一条会话，`parentSessionId` 指向原会话，对话拷到这一刻。

**API surface**:

本地 socket 上，一行一个 JSON。没有 HTTP。

| 消息 | 方向 | 关键输入 | 关键输出 | 谁可以发 | 关键错误 |
|---|---|---|---|---|---|
| hello | 终端到进程 | kind，cwd，sessionId 可空 | connectionId，sessionId | 本地用户的连接 | 地址没有进程且拉起失败 |
| resume | 终端到进程 | sessionId | 装回后的会话 | 该用户 | 会话文件不存在 |
| fork | 终端到进程 | sessionId | 新 sessionId，parentSessionId | 该用户 | 原会话不在这份进程里，也不在磁盘上 |
| turn | 终端到进程 | sessionId，用户输入 | 流式事件，一行一个 JSON | 当前附着的连接 | 会话不是 idle |
| cancel | 终端到进程 | sessionId，turnId | 这一轮已停 | 当前附着的连接 | 这一轮已经不在跑 |
| detach | 终端到进程 | connectionId | 会话已释放或仍有别的连接 | 当前连接 | 连接已经没了 |
| logout | 终端到进程 | 无 | 进程登录态已空 | 该用户 | 本来就没登录 |
| bg start | 终端到进程 | cwd，任务 | sessionId | 该用户 | 拉起失败 |
| bg list / logs / kill | 终端到进程 | sessionId 可空 | 会话列表、日志、已终止 | 该用户 | 会话不在这份进程里也不在磁盘上 |
| remote hello | 远程到进程 | 远程自身的连接凭证 | connectionId，sessionId | 已通过远程凭证的连接 | 凭证无效 |

**Value sourcing**:

| 动作 | 要给出的值 | 来源 |
|---|---|---|
| hello | connectionId | 进程当场生成 |
| hello / resume | sessionId | 请求里带来，或进程新建 |
| resume | 对话内容 | `<项目目录>/<sessionId>.jsonl` |
| fork | 新 sessionId | 进程当场生成 |
| fork | 拷到这一刻的对话 | 原会话 jsonl 里写完的行，加上当前这一轮已经流出来的输出。没流出来的不在内 |
| turn | 流式事件 | 进程内这一轮的模型输出 |
| detach | 会话还在不在内存 | 这份进程的会话表。断开时，没写完的那一行不进 jsonl |
| logout | 登录是否还在 | 进程里的那一份 auth |
| bg list | 会话状态 | 进程内会话表，加上磁盘上已释放会话的 jsonl |
| 默认地址 | 路径或管道名 | 没设置 `CLAUDE_SHARED_SOCKET` 时按平台默认。设置了就用它 |

- 一个用户同时只有一份这种进程。锁文件记录持有者进程号。
- 一个会话同时只有一个交互连接或一个远程连接。
- 后台会话没有活连接。它的一轮结束就从内存拿掉。
- 进程内不保留 `released` 的会话对象。
- 会话磁盘格式仍是现有 jsonl。分叉写出新的 jsonl，不改原文件。
- 写进 jsonl 的每一行都是完整的。写到一半的行在断开或崩溃时丢掉。
- 一轮对话里的异常只停这一轮。进程起不来或原生模块崩溃，才带走整份进程。
- 锁不被活进程持有时，才可以删残留地址。活着与否看锁文件里的进程号。
**Security model**:

- 本地 socket 只接受这个用户自己的连接。地址文件的权限是仅所有者。
- 远程连接必须带它自己的远程凭证。凭证过了，才允许用进程里的模型登录态。凭证不过，连接直接拒绝。
- 退出登录清空进程里的那一份，所有会话下次要模型时都要重新登录。
- 不新增个人数据存储。对话还在原来的会话文件里。

**Configuration required**:
- `CLAUDE_SHARED_SOCKET`: 改这份进程的本地地址。不设置就用平台默认地址。

**Critical test scenarios**:
- 两个终端先后打开，第二份不新起进程。验证 **AC-1**，**AC-2**。
- 关掉终端再打开同一会话，对话从 jsonl 回来，进程内在关掉期间没有这个会话。验证 **AC-3**。
- 会话正被一个终端用着，第二个终端打开它，得到新会话。新会话含已落盘的行和已流出的输出，原会话还在跑。验证 **AC-4**。
- 一轮跑到一半断开，这一轮停。写完的行还在，写到一半的行不在。验证 **AC-5**。
- 一轮里抛错只停该会话。把进程杀掉再打开，从 jsonl 恢复，不从内存恢复。验证 **AC-6**。
- 一个终端退出登录后，另一个会话的下一次模型调用不再带着旧登录。验证 **AC-7**。
- 后台任务跑完后从内存消失，`logs` 仍能从 jsonl 读到。验证 **AC-8**。
- 远程连接不再伴随一个 worker 子进程，并且用的是进程里的登录态。验证 **AC-9**。
- 设置 `CLAUDE_SHARED_SOCKET` 后，终端连到这个地址而不是默认地址。验证 **AC-10**。

## Build plan

1. 先做交互终端这一刀：用到才起、固定或可配置地址、残留地址清理、一行一个 JSON、会话表、单连接、断开即释放、从现有 jsonl 恢复、分叉。满足 **AC-1** 到 **AC-7**，**AC-10**。
2. 后台会话并入这一份进程，一轮结束就释放。满足 **AC-8**。
3. 远程控制并入这一份进程，去掉为它拉起的 worker 子进程。满足 **AC-9**。

顺序按 Skateboard。第 1 步就是你能打开两个终端并少付一份内存的那个整体。第 2 步和第 3 步把它长厚。

## Consequences

**Positive**:
- 多个终端、后台、远程共用一份运行时和一份登录态。
- 会话文件不用迁移。

**Negative / tradeoffs**:
- 原生崩溃会带走所有正在附着的会话。恢复靠磁盘，不靠内存。
- 退出登录是整份进程的，不是一个会话的。
- 分叉会多一份会话文件。原会话和分叉从那一刻起各写各的。
- 后台会话一轮结束就从内存拿掉。要接着看，得再附着，不能一直热着。

**Neutral**:
- 现有 `claude daemon` 监督进程留到远程控制并入之后再退。在那之前，两套进程入口会同时存在。

## Migration plan

**Strategy**: strangler
**Phases**:
1. 交互终端走新进程。旧的 `claude daemon` 和后台会话命令保持原样。
2. 后台会话改走这份进程。旧命令变成对新消息的转发。
3. 远程控制改走这份进程。确认没有人再依赖 worker 子进程后，监督进程停止再拉它。
**Rollback**: 每一相都可以把连接指回旧的独立进程。会话 jsonl 没改格式，回退不需要迁数据。
**Risks**: 第 1 相和第 2 相之间，交互终端已经在共享进程里，后台会话还是独立进程。这段时间内存只对交互终端下降。原生崩溃在共享进程里会影响所有正在附着的交互终端。
